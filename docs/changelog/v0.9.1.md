# 0.9.1

云同步按设备绑定接口对齐，并配合服务端的密钥代条件更新。客户端不连接邮箱服务器。

- 开启同步仍是：发送设备验证码 → `POST /api/sync/device/bind` → 按响应处理密钥包 → 上传或合并保险库。不插入官网登录 JWT。
- 云端已有密钥包时先下载并用官网密码解开，再用解开的密钥读取、合并远端保险库。不再用本机数据密钥覆盖已有密钥包。
- 云端没有密钥包但已有保险库时，先确认本机密钥能解开该库，才和密文一起原子提交。解不开则停止，不上传、不覆盖。
- 首次建立改为一次 `PUT /api/sync/commit`。重复提交同一份内容是幂等的。提交失败不会留下半更新；校验失败会解除刚创建的设备。
- 更换云端密钥是单独操作。必须先用当前密钥解开云端数据，合并两边可解密的条目并确认后，才提交新的密钥代和对应密文。失败、取消或未确认冲突时不改本地库。
- 其他设备下次同步发现密钥代变化后，暂停自动和手动同步，并提示到用户管理后台检查。不自动改密码，也不强迫接受新密钥。用新的 .kpkey 确认能解开云端密文并写回本地解锁文件之后，才恢复同步。还没同步的本地条目先合并保留。
- 密钥代建立之后，不带密钥版本的旧客户端上传会被拒绝。密钥代仍为 0 的旧库可以继续同步，直到某台 0.9.1 客户端完成首次建立或换钥。
- 绑定在保险库提交得到成功响应之后才显示已开启。上传前不把 `.sync` 写成已绑定。
- 设备验证码按服务端 `device_bind`：8 位字母数字、15 分钟。发送接口返回 200 只表示请求被接受，不表示邮件一定发出，也不说明账号是否存在。
- 客户端只用 HTTPS 请求服务端发验证码。绑定仍然提交网站账号密码和 .kpbind。客户端不读取邮箱登录密码或 SMTP 授权码，也不连接 IMAP、POP 或 SMTP。
- 网络不可达、超时、取消、TLS、401、403、409、422、426、429 和 5xx 使用固定中文提示。设备令牌失效或密钥代变化后停止轮询，保留本地保险库。
